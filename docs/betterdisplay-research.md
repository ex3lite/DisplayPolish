# DisplayPolish. Аудит оверяркости BetterDisplay 5.2.1

11 ноября 2026 года

Исследован пользовательский образ `BetterDisplay-v5.2.1.dmg`, сборка `5.2.1 (54014)`. SHA-256 совпал с релизом, подпись приложения и вложенных компонентов прошла проверку. Анализ основан на импортах Mach-O, строках и селекторах Objective-C, официальном руководстве и проверках DisplayPolish на M1 Max с macOS 27.2. BetterDisplay из образа не запускался. [Релиз](https://github.com/waydabber/BetterDisplay/releases/tag/v5.2.1) · [Контрольная сумма](https://github.com/waydabber/BetterDisplay/releases/expanded_assets/v5.2.1)

## Штатная яркость, клавиши и индикатор

Пользовательский визуал показывает округлый сегментированный индикатор, который появляется при изменении яркости клавишами. Пункт управления macOS и этот индикатор — разные поверхности.

- **Клавиши яркости.** BetterDisplay принимает штатные клавиши Apple с системным разрешением и сам выбирает дисплей и уровень. В бинарнике есть `AXIsProcessTrustedWithOptions`, `CGEventTapCreate` и `CGEventTapEnable`. Руководство описывает, когда BetterDisplay забирает управление и когда оставляет его macOS. [Native (Apple) Keyboard Control](https://betterdisplay.pro/guide/interface-reference/settings/keyboard/native-keyboard-control/)
- **Индикатор.** В 5.2.1 есть `OSDManager`, идентификатор `com.apple.OSDUIHelper` и методы `showImage:onDisplayID:…` для традиционной системной обратной связи. На macOS 27.2 BetterDisplay по умолчанию показывает собственный округлый сегментированный индикатор. Стиль System OSD из macOS 26 на macOS 27 переводится в режим под значком приложения. Так интерфейс повторяет визуал Apple, хотя шкалу рисует BetterDisplay. [OSD](https://betterdisplay.pro/guide/interface-reference/settings/keyboard/osd/)
- **Пункт управления.** Руководство показывает сценарий, где штатный ползунок меняет яркость, а BetterDisplay считывает изменение и передаёт его на выбранные дисплеи. В сборке есть `DisplayServicesRegisterForBrightnessChangeNotifications` и симметричное снятие подписки. Это подтверждает наблюдение за системной яркостью. Доказательств подмены самого виджета Control Center в исследованной сборке нет. [Синхронизация со штатной яркостью](https://betterdisplay.pro/guide/tutorials/external-automatic-brightness/)
- **Direct XDR.** На совместимых встроенных панелях BetterDisplay меняет аппаратный диапазон и состояние пресета. Руководство указывает, что приложение сохраняет прежние пресет, яркость и автояркость и рекомендует передать ему управление клавишами. Прежний метод с пресетом BetterDisplay XDR отключён начиная с macOS 26.3. В бинарнике найдены `SLSDisplaySetActivePresetIndex`, `DisplayServicesSetBrightness` и `edrEnforcerWindow`. Эти признаки не устанавливают точную последовательность аппаратных вызовов. [Методы XDR](https://betterdisplay.pro/guide/tutorials/xdr-and-hdr-brightness-upscaling/)

DisplayPolish проверяет доступ к клавишам при запуске и во время работы. До выдачи доступа меню показывает **Grant Access…**. После выдачи приложение сразу запускает перехват и показывает переключатель **Use brightness keys**. Выбор пользователя сохраняется.

Control Center в macOS 27.2 передаёт диапазон, уровень яркости и ID дисплея в `SystemBannerUI`. Дизассемблирование ARM64e-функции `DisplayBrightnessSystemBannerContent.sliderBannerImage(for:)` показывает выбор `sun.min` при уровне ниже `0.333` и `sun.max` начиная с `0.333`. Системная библиотека доступна в dyld shared cache по пути `/System/Library/PrivateFrameworks/SystemBannerUI.framework/Versions/A/SystemBannerUI`.

DisplayPolish использует этот же порог. Солнце появляется и затухает вместе с капсулой. Кривые прозрачности и масштаба подобраны по записи штатной шкалы. Капсула использует `NSGlassEffectView` поверх размытия окон за панелью. На шкале есть отметка 100%, отдельная зона XDR и фактический процент усиления. Обработчик выбирает дисплей по положению курсора. [AppKit Liquid Glass](https://developer.apple.com/documentation/appkit/nsglasseffectview)

## Реализация XDR

BetterDisplay предлагает цветовые таблицы на совместимых Apple Silicon, Metal как программный путь и прямое управление на отдельных встроенных XDR-панелях. На M1 Max с macOS 27.2 пробник записал RGB-кривые с пиком `1,20` после включения EDR-слоя. CoreGraphics сообщил об успехе, но чтение вернуло пик `1,00`. Откат восстановил исходные кривые. SDK документирует диапазон таблиц `0…1`. [Apple DTS о цветовых таблицах](https://developer.apple.com/forums/thread/819331)

DisplayPolish использует отдельное прозрачное для ввода окно на каждом активном дисплее. `CAMetalLayer` растягивает однопиксельный буфер `.rgba16Float` в `extendedLinearDisplayP3`. Недокументированный режим `multiply` композитора осветляет рабочий стол. Запрошенный коэффициент, доступный EDR и окно хранятся по текущему ID дисплея. При изменении расположения дисплеев слой пересоздаётся только для экрана, чьи границы изменились. Отключение дисплея закрывает его слой. Независимое управление доступно в расширенном рабочем столе. [Apple о Metal и EDR](https://developer.apple.com/documentation/metal/performing-your-own-tone-mapping) · [Открытый пример Metal и multiply](https://github.com/levelsio/xdr-boost)

На совместимом дисплее Apple участок ползунка до 100% управляет аппаратной яркостью через `DisplayServices`. Выше 100% аппаратная яркость устанавливается на максимум и добавляется Metal-слой. На остальных совместимых HDR-экранах шкала начинается со 100%. Возврат на 100% снимает слой с выбранного экрана. [Combined brightness в BetterDisplay](https://betterdisplay.pro/guide/interface-reference/app-menu/device-menu/sliders/)

HDR-захват двух серых тестовых окон подтвердил независимое усиление на встроенном Retina и подключённом Mi monitor. При включении обоих линейный RGB вырос с `0,1030` до `0,1264` на Retina и с `0,1005` до `0,1068` на Mi. После выключения Retina вернулся к `0,1030`, а Mi сохранил `0,1068`. Выключение обоих вернуло исходные значения. В этом сеансе macOS дала Mi коэффициент `1,067` при запросе `1,40`. Эти числа описывают компоновку изображения. Физическая яркость в нитах не измерялась.

Проверка запаса XDR обновляет отображаемую оценку. Metal-кадр меняется при регулировке или пересоздании окна дисплея. Скрытие HUD выполняет `orderOut` только для окна индикатора.

При проверке отката без захвата экрана один HUD сохранял исходный предел драйвера встроенной панели около 600 нит. Metal-слой при запросе 156% поднимал предел и без HUD. В отдельном прогоне с клавишами XDR-окно оставалось на экране после скрытия HUD, а показания драйвера не снижались. Телеметрия драйвера не измеряет оптическую яркость изображения. Пользовательский откат в этих прогонах не воспроизвёлся.

Дополнительный анализ ARM64 BetterDisplay 5.2.1 подтвердил вызовы `IORegistryEntrySetCFProperty` для `BLNitsCap`, `IOMFBBrightnessLevel` и связанных лимитов. На встроенной панели M1 Max запись `BLNitsCap` и `IOMFBBrightnessLevel` в формате 16.16 удерживала 700 нит по данным драйвера без графических окон. DisplayPolish использует эти два свойства при однозначном обнаружении совместимой встроенной панели, ограничивает запрос калибровкой и физическим пределом и сохраняет исходные значения для восстановления. Для остальных дисплеев действует Metal.
